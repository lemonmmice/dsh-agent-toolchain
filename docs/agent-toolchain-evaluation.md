# Agent 工具链全面评估与优化

评估日期：2026-09-20（当地时间；运行记录为 2026-09-21 UTC）。环境：Windows x64、Node.js 24.15.0。评估对象是当前工作区，包含前一轮尚未提交的 UI P0–P2 改动；本文仅把这次新增的优化计入本轮收益。

本文记录第一阶段的基准与优化，不代表 53 个工具都已完成真实业务验收。用户后续要求的逐工具真实客户端验收，单独记录在本地忽略目录 `bench-runs/real-client-acceptance/`，按批次持续推进。

## 总体判断

这套工具链已经具备完整的工程证据闭环，适合继续作为 agent 的日常工具。本轮最大的收益来自调用路径和协议正确性：减少无谓进程启动，让等待和取消符合调用者预期，准确表达失败与不完整结果，并限制输入输出的资源消耗。

目前不建议继续大面积 Rust 重写。已经迁移的四个核心有实际收益；MCP、UI 调度、网络等待、外部分析器等路径的主要问题不能仅靠更换语言解决。继续保持 JS 编排、Rust 计算/存储、C#/系统工具处理专用诊断的分工。

## 评估方法与覆盖范围

本轮结合源码审查、真实 stdio MCP 往返、本机回环 HTTP 服务、隔离 PowerShell 协议进程、临时文件/索引、故障注入、原生与旧实现对照基准，以及仓库回归测试。问题先复现，再修改生产实现。

| 维度 | 检查重点 | 结论 |
| --- | --- | --- |
| 调用顺手程度 | 工具发现、选择、参数、顺序组合、下一步提示 | 能力完整；修正错误标记与诊断脚本顺序；工具发现体积仍大 |
| 响应速度 | 冷启动、常驻调用、自检、子进程数量 | 自检明显加速；并发首次 UI 调用共享启动握手 |
| 及时反馈 | 首次反馈、长任务心跳、完成/失败通知 | MCP 加入标准 progress；显示取决于客户端支持 |
| 结果可信度 | 未执行/未知/失败、截断、缓存身份 | 修复拒绝操作假成功、排队误杀、缓存碰撞及截断表达 |
| 超时与取消 | 网络正文、后台任务、等待计时器 | HTTP 支持取消；修复 embedding 正文超时和 hang 等待 |
| 内存与数据边界 | 大响应、大日志、多文本输出 | HTTP 与日志读取有界；输出预算保持明确的不完整契约 |
| 隐私 | 进度、错误、自动失败记录 | 不在进度带参数；HTTP 自动失败记录不保存请求 URL |
| 维护与部署 | 双接口一致性、测试、可重复测量 | 保留共享实现，增加可重复 MCP 基准和针对性回归 |

没有把隔离 mock 的耗时当成真实 UIA 耗时，没有把源码审查当成真实 ETW/dump 验证。本轮没有操作业务客户端或采集其 dump/ETW，没有使用真实远程 embedding API、上传截图或修改真实记忆库。测试使用的临时窗口/进程、受控故障证据和回环服务属于验证夹具。

## 本轮实现细节

### 1. 环境自检

`envValues` 只在一次调用内复用注册表文本，仍沿用现有解析和来源规则，保持进程环境 > 用户 > 机器优先级，显式空字符串继续禁止回退。每次自检重新读取，避免用缓存速度换取过期结论。

默认进程探测改用 .NET 批量读取 ProcessName/PID，避免 `tasklist` 在当前机器上约 2 秒的成本。探测有 5 秒上限，失败仍表达未知。dump 工具解析显式使用本次配置快照和传入的工具根，修复其与其他自检项新鲜度不一致的问题。

边界：接口仍同步；通常约 0.4 秒内结束，但外部探测异常及 `deep=true` 扫描仍可能占用事件循环。这次没有引入跨调用状态缓存。

### 2. UI 常驻会话

首次启动的并发调用共用一个握手 Promise。常驻进程只发出一个 active 请求，其余保留在明确的队列中。

排队到期返回 `queueTimeout:true`、`notExecuted:true`，不会杀掉正在执行的动作，也不会自动重放。已发出的操作超时仍保持“结果可能未知”的既有含义；不把它说成从未执行。证据记录也据此设置 executed。

对于不杀进程的截图超时，等待迟到响应后再继续调度，避免同一截图重复下发。`warmStatus` 增加 queued/executing，便于区分队列拥堵与执行中。

边界：同一桌面的输入本来就不能任意并行；授权、窗口身份、快照新鲜度和敏感字段检查没有为追求速度被跳过。

### 3. MCP 反馈、错误与取消

统一包装入口识别 `_meta.progressToken`，发送 started/running/completed/failed 通知。只包含工具名、状态和耗时，不包含参数、响应、异常正文或凭据。通知通道失败或反压不阻塞工具结果；完成、异常和取消会清理心跳。

无进度 token 时不发通知。running 是存活提示，不是已完成百分比，也不能证明底层外部程序仍有实质进展。同步阻塞会推迟心跳；客户端是否显示由客户端决定。

拒绝执行、缺少证据包、被拒绝的记忆写入/失败记录/验证报告返回结构化失败和 MCP `isError:true`。HTTP 非 2xx 继续表示“已收到 HTTP 响应”，调用者应看 status 判断业务状态。

MCP 取消信号传给 HTTP 实际 fetch 和响应读取。取消不代表远端撤销已经接受的请求；其他 build/perf/UI 工具继续使用其现有超时和 stop 控制，本文不宣称已经实现全工具底层取消。

### 4. HTTP 与 embedding

HTTP 按流读取并限制保留体积。超过 2 MiB 后取消继续读取，返回 `truncated:true`、`sizeExact:false`、`retainedBytes` 和解释；size 此时是已收到字节的下限。未截断响应仍给出准确大小，UTF-8 截断不制造残缺字符。

外部取消和内部 timeout 分开表达。自动失败语料不再写入原始 URL，防止 query 中的 token 随日志持久化；用户取消也不会被自动记成工具故障。

Embedding 的超时覆盖头部和 JSON 正文。非成功响应不读取并回显服务端正文，失败给出不含凭据的原因类别；响应向量必须是非空有限数字数组。缓存键使用 SHA-256(endpoint, model, text)，旧短键缓存不再读取，旧文件不主动删除。

### 5. hang 分析等待

新分析和证据变化重算通过统一等待辅助函数，提前完成或失败时均清理 timeout。已有分析正在运行时，`wait=true` 按预算等待状态变化，而不是立即返回 running。预算用尽仍诚实返回当前状态，不假装分析完成。

同时修正工具描述：源码行号表示方法声明位置，单次 dump 未必能确定等待对象或根因。删除 UI flow 固定“10 步 1–2 秒”的承诺，解释普通批处理与逐步授权的区别。

### 6. 输出预算与日志读取

输出预算继续默认关闭。开启 `DSH_OUTPUT_MAX_TOKENS` 后，全部 `content.text` 按顺序共享预算，先为末尾的唯一说明块预留开销。超限 JSON 变为合法的 `{outputBudget:{truncated:true,originalFormat:'json'},previewText:...}`，不继续伪装原来的完整对象。极小预算容不下最低说明时明确报告实际最小开销；图片、资源与 structuredContent 原样保留，不属于文本 token 预算。

通用字符串截断移除了全量 `Array.from` 字符数组。独立子进程的 2 MiB 文本单次诊断，堆增长约 18.15 → 2.13 MiB，耗时约 64 → 42 ms；这不是峰值 RSS 或多轮统计。JSON 识别仍会解析原文，不能拿输出预算替代生产者内存上限。独立复核额外覆盖 4480 种小规模输入/预算组合，未发现未披露超预算或非文本块丢失。

`LogTailer` 默认每次最多读取 1 MiB，单行上限 32 MiB。后者为请求和响应各 2 MiB、最坏 JSON 转义预留空间；约 24 MiB 的合法夹具已验证能够完整处理。半行按字节保留，完整行才解码 UTF-8；超长行丢弃到换行后恢复。`pendingBytes`、`bufferedBytes`、`discardingLine`、`oversizedLines`、`droppedBytes` 和 `dataComplete` 对外可见。

回调失败时不推进当前读取的 offset/半行/计数，仍按原有重试上限处理；最终丢弃按真实字节计数。轮转清空旧半行状态。每次 1 MiB 是 I/O 预算，不是整个宿主的内存上限；合法长行的保留及解析仍有成本。

### 7. 调试工具与复测入口

`mcp/probe.mjs` 使用仓库已有 MCP SDK 处理初始化、协议错误、超时和连接关闭，删除手写积累全部 stdout 并反复重解析的路径。`--seq` 真正串行执行；失败结束后不继续后续动作。进度写 stderr，结果写 stdout；不打印请求参数。

新增 `npm run bench:mcp`，方便日后区分是工具变慢、宿主启动变慢，还是外部依赖变慢。基准只记录时延、体积和状态，不采集业务数据。

## 各工具域的使用建议

| 需求 | 优先路径 | 使用边界 |
| --- | --- | --- |
| 开始构建/运行/诊断 | 先 `toolchain_status`，确认目标和依赖 | 环境自检通过不代表业务流程通过 |
| UI 交互 | `ui_observe` → 定位 → `ui_act`/`ui_drive` | 用明确 PID/HWND；定位失败先更新观察 |
| 固定 UI 流程 | `ui_flow` | 后续动作依赖画面判断时改为分步；不要盲目预排 |
| 已记录动作复测 | `ui_replay` | 重新校验目标、权限和当前状态 |
| 编译结果 | `build_run` → `build_errors`/`build_status` → `verify_report` | 保留指定工程、配置和源码归属证据 |
| 页面请求 | `capture_status` → 窄条件 `capture_query` | 少量摘要优先；需要正文再 includeBody |
| 主动接口验证 | `http_request` | 2xx 不一定业务成功；明确处理截断与超时 |
| 运行中卡顿 | 短时间采样、窄进程范围、查看对应报告 | 外部符号下载/ETL 解码可能主导耗时 |
| 卡死证据 | `hang_packs` → `hang_pack` → `hang_analyze` | 检查采集时间；托管栈与原生 unwind 能力不能混称 |
| 项目长期约定 | 按 scope 保存/检索 `memory_*` | 不保存凭据；修改源码后注意检索新鲜度 |
| 任务完成判断 | `verify_report` | 未配置、未采集、不完整、失败和成功分开报告 |

### 部署时发现并修复的问题

实际部署遇到 `EPIPE`：插件目录的递归复制试图覆盖内容未变化、但正在被宿主加载的原生模块。部署脚本现只复制缺失或哈希变化的文件，避免无谓覆盖；同时修复初次部署嵌套共享目录时未创建父目录的问题。新增部署回归验证了未变更二进制不改写、嵌套新增文件、共享模块和无变化部署不刷新部署戳。随后真实部署成功，插件和共享模块 `--check` 均为 0 drift。

## 后续优化的优先级与取舍

### 优先但需要另一个明确实施批次

1. **build/perf 的真正取消与后台任务协议。** MCP 通知改善等待体验，不能替代进程树、ETW 会话与证据文件的协作取消。应先给每个外部操作定义取消后状态，再引入 jobId/status/cancel，避免留下 ETW 会话或半份证据。
2. **减少首次工具发现的上下文成本。** 53 个工具的原始描述约 21k 估算 tokens。可研究按任务分组或客户端延迟发现；不应直接隐藏工具或删除权限/数据完整性说明，让 agent 在需要时找不到能力。
3. **大报告按域分页。** 通用输出预算只能保护返回文本，不能减少底层的全量计算。线程栈、树和大包应优先给摘要、计数、定位 ID，再按需读取明细。
4. **把仍同步的重 I/O 隔离出去。** 自检、源文件扫描和部分 native 同步操作仍占事件循环。只有复现其影响并发调用/心跳后再引入异步或 worker，避免增加线程间缓存和状态复杂度。
5. **对真实工作流建立长期性能样本。** 本轮给出可复测入口；生产 P95/P99、冷缓存、大型证据、低内存与长会话需要持续采样，不能从几次开发机基准推断。

### 当前不建议做

- 全工具重写 Rust：本轮发现的大部分关键问题属于协议和生命周期。
- 缓存整份环境自检或窗口授权：速度收益会以状态过期为代价。
- 对超时副作用自动重试：可能重复点击、提交或采集。
- 为减少输出而无声截断、返回零条或默认成功。
- 统一启用所有重型诊断：dump、符号解析、ETW、UI 树全量遍历不是低成本观察。
